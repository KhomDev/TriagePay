The agent signs. The contract decides.

Agents pay per call over x402 on NEAR, and the wallet is the security layer that makes that safe. Every payment is checked on chain against the owner's allowlist and caps, so a tricked agent cannot pay an attacker.

        Why it's different

        1. The limits live in the contract

          The agent key can call only pay. The allowlist, both caps, pause and revoke are enforced by the wallet contract, so nothing in the agent's prompt or code can lift them.

          See the agent key

        2. The owner reviews large payments on chain

          Above the threshold, the contract holds the payment until the owner approves or rejects it.

          Held on testnet

        3. The server reads the token's own event

          An x402 payment counts only when the token contract's own transfer event pays the gateway with the memo the server issued. Run on testnet and on mainnet in USDC.

          How the check works
        How it works

        The key can only ask. The wallet decides.

        1. Pay-only key. The agent account's key can call pay on one wallet. Signing happens on the server. This page never holds a key.
        2. The contract checks. Pause, the agent is active, the token, the allowlist, the per-call cap, the daily cap. An amount above the threshold is held for the owner.
        3. The refusal is a transaction. ERR_PAYEE_NOT_ALLOWED changes no balance. The explorer link is the proof.
